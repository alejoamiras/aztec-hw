The 5-year-old version

Right now our Ledger code lives in one box (adapter-ledger) that mixes two different things:

  • The reusable bit — "talk to a Ledger and get an Aztec account." Anyone could use this.
  • The demo bit — our specific test app: it knows about USDC/the faucet, spins up a prover (PXE), and runs deploy/drip/transfer. Nobody else wants this.

We're going to split the box in two: a clean aztec-ledger SDK (the reusable bit) that a stranger can npm install and use, and the demo bit moves into the demo app where it belongs. The tell that we cut correctly: the heavy demo-only libraries (@aztec/pxe, @aztec/noir-contracts.js, @aztec/wallets) must completely disappear from the SDK.

"Publish-quality but private" = we make it look and behave like a shippable npm package (clean API, a real build, docs, 3 ways to plug in a device), but we keep it private until the Ledger app itself is installable from Ledger Live. Until then, a developer can still side-load the dev app and connect through the SDK.

What a stranger gets afterward

import { connectLedger } from 'aztec-ledger';
import { webhid } from 'aztec-ledger/webhid';        // or /node-hid, or /speculos (tests)

const conn = await connectLedger({ transport: webhid() });   // fails closed if the firmware is wrong
const account = await conn.createAccount({ scheme: 'ecdsa' }); // device-attested address by default
// → use `account` with @aztec/aztec.js like any account

The non-obvious truths the planning surfaced

FindingSo we…
The root barrel re-exports the demo session + transports → the "no heavy deps" promise leaks at the public API.Cut a tiny ~12-symbol root barrel first; demote internals/transports/raw-signer/reveal to subpaths.
We feared the call-decoder was glued to the demo's contract list. It isn't — the only glue is one host-side "early reject" check, and the device re-checks everything anyway (codex + opus both verified this in the firmware).Make that check an optional hook; the SDK ships no contract list. Consumers bring their own (matched to their firmware) or skip it.
The code-generator also writes the firmware's tables and pulls a heavy lib.It moves to a shared tools/ dir — not in the SDK, not buried in the demo.
There's no build step today (we ship raw TypeScript).Add a real emitter (tsup → JS + types). Spike it early — 29 deep @aztec/* imports could bite.
"Keys never leave the device" is false. The spend key stays, but onboarding reveals the viewing/privacy root to the browser by design.Say so plainly; put reveal/onboarding on an ./advanced subpath that's explicitly outside the safe-by-default guarantees.
