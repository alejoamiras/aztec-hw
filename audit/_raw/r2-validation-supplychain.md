## Tightened detail — VALID-NEW only

### NEW-R2-01 · HIGH · BUILD · OURS
**CI typecheck gate is red on committed `main`.** `ci.yml:36` runs `bunx tsc -b --noEmit packages/core packages/adapter-trezor packages/adapter-ledger apps/demo`; re-run on HEAD → **exit 2, 8 errors**. Two root causes: (a) net-new `noUncheckedIndexedAccess` violations in LIVE test files (`grumpkin-point-add-edge.test.ts:30` `o[0]/o[1]`; `wire-differential-replay.test.ts:158` `files[i]/lines[i]/split()[1]`) — unrelated to AHW-028; (b) `apps/demo` calling the deleted `createAuthWitFromIntent` (overlaps AHW-028's cause, but the red-gate consequence is new). Impact: the PR typecheck gate fails on every run, so either it is being merged-around (false CI-green assurance, real type regressions can land) or branch protection doesn't require it. **Fix:** guard the two test-file index accesses; delete/repair `apps/demo` (NEW-R2-02); confirm branch protection requires the typecheck job green.

### NEW-R2-02 · MED · BUILD · OURS
**Inverted CI coverage: the dead CLI demo is gated, the live browser demo isn't.** `ci.yml:36` typechecks `apps/demo`; grep confirms `apps/demo-browser` appears in zero workflows and there is no Playwright job, despite `apps/demo-browser/playwright.config.ts` + `e2e/` existing. The shipped/recorded demo (React+Vite in-browser PXE, with the security-relevant clear-signing panels) has no typecheck and no e2e in CI; regressions land silently. **Fix:** swap `apps/demo → apps/demo-browser` (or include both once apps/demo is fixed) in the typecheck list; wire `tsc --noEmit -p apps/demo-browser` + at least one Playwright smoke job (infra already exists).

### NEW-R2-03 · LOW · BUILD · OURS
**`tsc -b` against non-composite projects — fragile build graph.** `ci.yml:36` and `apps/demo-browser/package.json:8` use build mode (`tsc -b`), but no tsconfig sets `composite:true` and the root has no `references` (grep empty). Build mode is defined for composite graphs; on a flat path list of non-composite projects its project selection / `.tsbuildinfo` caching / error attribution is fragile, and a future tsconfig tweak could silently shrink what's checked — a gate that quietly stops gating. **Fix:** either make packages truly composite, or (preferred for a PoC) drop build mode for explicit `tsc --noEmit -p <each>`.

### NEW-R2-04 · MED · BUILD · OURS
**`bun audit` advisory but findings never surfaced.** `ci.yml:41-43` runs `bun audit` with `continue-on-error:true`, no `$GITHUB_STEP_SUMMARY`, no `--json`. Verified: exit 1, 12 vulns / 6 HIGH (4× `systeminformation` command-injection via `@aztec/bb-prover`/`@aztec/pxe`; 2× `undici` via `@aztec/foundation`). CLAUDE.md policy is "advisory AND surface in step summary" — only the first half exists, so 6 HIGH advisories are invisible on every PR and a NEW (possibly direct) advisory would go unnoticed. **Fix:** pipe `bun audit --json` into a step that appends a table to `$GITHUB_STEP_SUMMARY` (keep `continue-on-error` if noise is the concern); triage/accept-with-rationale the transitive systeminformation/undici HIGHs.

### NEW-R2-05 · MED · DESIGN · OURS
**Embedded firmware source has no integrity link.** Parent tracks 159 `ledger-app/**` files as mode-100644 blobs with no `.gitmodules`; the nested `ledger-app/.git` is a separate repo whose branch `main` has ZERO commits (73 files staged `A`, never committed), and `ledger-app/.git/` is gitignored by the parent (`.gitignore:32`). Two independently-mutable copies of the BOLOS firmware exist with no pinned SHA/hash and no provenance — for a HW wallet, no way to prove "audited firmware == shipped firmware", and the orphan `.git` invites edits in the wrong tree that silently diverge. `ledger-app/ledger_app.toml` claims it's a "self-describing Ledger project" for submission, but its repo is empty. **Fix:** pick one model — (a) real submodule pinned to a commit SHA, or (b) absorb fully (delete the orphan `.git`, single source of truth, record a firmware build hash in CI artifacts). Today it's neither.

### NEW-R2-06 · MED · BUILD · OURS
**Clear-signing codegen trusts mutable `node_modules` artifacts; the pin is a comment.** `gen-clear-signing-v0.ts:26-34` reads `token_contract-Token.json` / `dripper-Dripper.json` from `packages/adapter-ledger/node_modules/@defi-wonderland/aztec-standards/target/` (install-time-resolved). `manifest.json:_meta.aztec_standards_npm_pin` (`4.2.0-aztecnr-rc.2`) is echoed only into generated-file header comments (script lines 260-261); the script never asserts the installed `package.json` version equals the pin nor a content hash of the two artifacts. The whole manifest-selector cross-check (codex BLOCKER #2 / underpins AHW-003) thus validates against whatever is on disk. `bun.lock` blocks a same-tag re-point but not a reviewed-looking dep bump or in-tree artifact tampering. **Fix:** at codegen/check time assert installed version === `_meta` pin AND SHA-256 the two artifacts into `_meta`, fail-closed on mismatch.

### NEW-R2-07 · MED · HOST · OURS
**`adapter-trezor` replicates the blind-sign hole AND ships a self-described spoofable clear-sign path.** `packages/adapter-trezor/src/provider.ts`: `createAuthWit` (81-86) is a pure blind sign over `ecdsaPreimage(outerHash)` (the AHW-001 pattern, in a second adapter); `createAuthWitFromIntent` (99-104) is, per its own doc-comment (88-98), "decorative only … a malicious host could show benign visual text while signing a malicious digest." The class `implements IntentAuthWitnessProvider` (46), so callers get a false clear-sign guarantee. It is exported, typechecked in `ci.yml`, and run by `bun test`. Distinct from AHW-001 (different package) and AHW-012 (a scheme-generic *name*, vs here a *decorative method typed as intent-binding*). **Fix:** decide explicitly — if dead, move to a `research/` path excluded from CI typecheck/test and published exports with a README banner; if kept, make `createAuthWit` fail-closed and either remove `createAuthWitFromIntent` or gate it behind an explicit `UNSAFE_DECORATIVE` flag so the type stops lying. (Note: production-grade Trezor clear-sign needs on-device Poseidon2, which current Trezor firmware can't meet.)

### NEW-R2-08 · LOW · BUILD · OURS
**Crypto-library version fragmentation.** `bun.lock`: `@noble/curves` resolves to 2 resident versions (1.7.0, 1.9.1); `@noble/hashes` to 3 (1.6.0, 1.8.0, **2.2.0** — a genuine v1↔v2 major split, 2.2.0 pulled via `@scure/bip39`); `typescript` is `^6.0.3` (root, resolves 6.0.3) vs `^5.7.0` (apps/demo-browser). Direct dep `@noble/secp256k1 ^3.1.0` appears in adapter-ledger, adapter-trezor, apps/demo. For a wallet, multiple resident EC/hash versions widen the CVE blast radius (each line patched independently) and the live demo compiles under a different TS major than the libs it consumes. Most `@noble` fan-out is transitive via `@aztec/*` (not directly fixable). **Fix:** add `overrides`/`resolutions` to collapse `@noble/curves`+`@noble/hashes` where the graph allows; align TypeScript to one major; document irreducible transitive dups. (Folds in NEW-R2-09: hoist shared dev tooling — `typescript`, `vite-plugin-node-polyfills` — to root, drop the drifted per-app copies.)

### NEW-R2-10 · LOW · DESIGN · OURS
**"Forget" over-promises + recovery model undocumented.** (1) `secret-cache.ts:58-66` `clearAllCachedSecrets` drops Map/sessionStorage refs but never zeroizes the immutable hex strings or the `Fr` instances already handed to callers (`loadCachedSecret:48`); JS can't scrub them, so a heap snapshot / extension after "Forget" may still recover a viewing-root-grade secret. `ConnectPanel.tsx:onForget` / its "genuinely empty browser" copy implies a wipe the platform can't deliver. (2) The re-derivation custody model is correct (verified: in-memory PXE + walletDB, no localStorage/IndexedDB; reconnect == recovery) but there is no `docs/recovery.md` (grep → only incidental roadmap.md mention) telling users "device seed is the only backup, viewing root is always re-derived, nothing is exported." LOW: the browser-untrusted model is already documented in the cache header; the gap is copy + a missing doc. **Fix:** best-effort zeroize backing stores where the runtime allows and soften "Forget" → "Clear this session"; add a short recovery/custody doc.

### NEW-R2-11 · INFO · BUILD · OURS
**Lockfile-freeze is single-point-of-discipline.** `bunfig.toml` `frozen=false` (correct per "local updates, CI freezes"); enforced only by `bun install --frozen-lockfile` in `ci.yml:27` + `ledger-app.yml:93`. `bun.lock` committed; `minimumReleaseAgeExcludes` commented out (no active bypass). No bug, but a future workflow that forgets the flag (e.g. a publish/deploy job) would silently resolve un-committed dep changes. **Fix (optional, PoC):** a composite action that always installs with the frozen flag, or a convention test.
